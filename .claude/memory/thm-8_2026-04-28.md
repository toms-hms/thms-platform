## Summary

Establishes the vendor module and its data model. A vendor can carry multiple
trade categories and multiple service ZIP codes, so the model normalizes those
into `VendorCategory` and `VendorZipCode` join tables alongside the core
`Vendor` model, with a `VendorManager` owning CRUD and relation access. Ships
the full module slice — shared `Vendor` types, zod `schema`, mutation-only
`service`, `route`, a test factory, and wire/auth route tests — registered in
the db schema and mounted in `app.ts`. This is the backend foundation that the
later contractor-matching work (THM-10) queries by category and ZIP.
